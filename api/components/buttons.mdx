## Overview

Buttons in BotTroner provide interactive controls for users. Each button has a unique custom ID that triggers specific handler logic when clicked.

## Button Categories

<Tabs>
  <Tab title="Virtualization Buttons">
    ### VM Start Button
    
    Starts a virtual machine.
    
    **Custom ID:** `vm-start_{vmId}`
    
    **Location:** `src/components/virtualization-buttons/vm-start.ts:6`
    
    **Optional Parameters:**
    - `id` (string): The VM identifier
    
    **Example Usage:**
    ```typescript
    const startBtn = new ButtonBuilder()
      .setCustomId(`vm-start_${vm.id}`)
      .setLabel("Iniciar")
      .setEmoji("🟢")
      .setStyle(ButtonStyle.Success)
      .setDisabled(vm.status === "running");
    ```
    
    **Interaction Flow:**
    1. User clicks the start button
    2. Handler defers the update
    3. Finds the panel for the VM
    4. Executes the start action via `vmManager.executeVMAction()`
    5. Sends feedback to the user

## Creating Custom Buttons

To create a new button component:

1. Create a new file in the appropriate category folder (e.g., `src/components/my-category-buttons/`)
2. Export the required properties:

```typescript
import type { Buttons } from "@src/types/components";
import type { ButtonInteraction } from "discord.js";

export const data: Buttons["data"] = {
    name: "my-button"
}

export const optionalParams: Buttons["optionalParams"] = {
    id: "string" // Optional: define parameters
}

export const type: Buttons["type"] = "button";

export const run: Buttons["run"] = async ({ interaction, client, optionalParams }) => {
    // Your button logic here
    await (interaction as ButtonInteraction).deferUpdate();
    
    // Process the interaction
    const id = optionalParams?.["id"] as string;
    
    // Respond to user
    await interaction.followUp({
        content: "Button clicked!",
        flags: MessageFlags.Ephemeral
    });
}
```

3. The button will be automatically loaded by the component handler

## Button Naming Convention

Button custom IDs follow this pattern:
```
{category}-{action}_{optionalParams}
```

Examples:
- `vm-start_12345` - VM start button with VM ID 12345
- `ticket-new` - New ticket button (no parameters)
- `announce-confirm_a1b2c3d4` - Announce confirm with hash parameter

## Best Practices

1. **Always defer updates** for buttons that perform async operations
2. **Use ephemeral messages** for error feedback
3. **Validate permissions** before executing sensitive actions
4. **Handle errors gracefully** with user-friendly messages
5. **Use type assertions** when narrowing interaction types
6. **Clean up resources** (e.g., delete temporary data after use)
